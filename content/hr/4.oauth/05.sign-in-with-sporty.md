Ako vam treba samo znati tko je netko, trebate OpenID Connect, a to je
[tok authorization code](/hr/oauth/authorization-code) s `openid` u opsegu.

Usmjerite bilo koju OIDC biblioteku na `https://api.sporty.plus/.well-known/openid-configuration`
i ona će se sama konfigurirati. Provjeru je moguće napisati i ručno, ali to se rijetko isplati.

## Dobivanje client id-a

Svatko sa Sporty računom može registrirati aplikaciju pod
[**Za developere**](https://my.sporty.plus/my/developer) u izborniku svog računa. Trebate:

- **URI za preusmjeravanje**, na koji Sporty vraća ljude s kodom;
- po želji **URI za preusmjeravanje nakon odjave**, kamo Sporty smije poslati ljude nakon što
  se odjave (vidi *Odjava* u nastavku);
- odgovor na pitanje **ima li vaša aplikacija poslužitelj koji može čuvati tajnu**. Isključite to
  za aplikaciju koja radi samo u pregledniku ili na mobitelu. Tada ne dobiva tajnu i prijavljuje se
  samo s PKCE-om.

Nova aplikacija radi **samo za vas** dok je Sporty ne pregleda. Izgradite je i isprobajte do kraja,
a zatim nam se [javite](mailto:info@sporty.plus) da je pregledamo. Do tada svi ostali koji je
pokušaju koristiti vide upozorenje, a prijava ne prolazi.

Aplikaciju izgrađenu za jedan klub može registrirati i administrator tog kluba, pod
**Postavke → API klijenti**. Vidi [Registracija aplikacije](/hr/oauth/clients).

## id_token

Vraća se uz pristupni token kad je odobren `openid`. To je RS256 JWT:

```json
{
  "iss": "https://api.sporty.plus",
  "sub": "9f1c2e40-...",
  "aud": "your-client-id",
  "iat": 1789304059,
  "nbf": 1789304059,
  "exp": 1789307659,
  "auth_time": 1789301200,
  "amr": ["pwd", "otp", "mfa"],
  "nonce": "what-you-sent",
  "at_hash": "xQ7f...",
  "name": "Ada Lovelace",
  "given_name": "Ada",
  "family_name": "Lovelace",
  "locale": "hr",
  "picture": "https://...",
  "email": "ada@example.com",
  "email_verified": true
}
```

| Claim | Napomene |
| --- | --- |
| `sub` | Trajni id člana. **Upravo njega pohranite.** Nikad se ne mijenja; adresa e-pošte može se promijeniti. |
| `aud` | Vaš client id. Provjerite ga. |
| `nonce` | Prisutan ako ste ga poslali. Provjerite ga. |
| `at_hash` | Veže ovaj id_token uz pristupni token izdan zajedno s njim. |
| `auth_time` | Kad se član prijavio u Sporty. Za nekoliko sesija starijih od ove mogućnosti to je trenutak kad je odobrio vašu aplikaciju. |
| `amr` | Kako se prijavio, vidi u nastavku. Nema ga za te iste starije sesije. |
| `name`, `given_name`, `family_name`, `locale`, `picture` | Uz `profile`. |
| `email`, `email_verified` | Uz `email`. |
| `phone_number`, `phone_number_verified` | Uz `phone`, kad član ima broj. `phone_number_verified` je uvijek `false`: Sporty ne provjerava brojeve telefona. |
| `clubs` | Uz `clubs`, vidi u nastavku. |

### Kako se član prijavio

`amr` koristi vrijednosti iz [RFC 8176](https://www.rfc-editor.org/rfc/rfc8176):

| `amr` | Prijava |
| --- | --- |
| `["pwd"]` | Lozinka |
| `["pwd", "otp", "mfa"]` | Lozinka i kod iz aplikacije za autentifikaciju |
| `["pwd", "mfa"]` | Lozinka i kod za oporavak |
| `["hwk", "mfa"]` | Pristupni ključ (passkey) |
| `["fed"]` | Google, Apple, Microsoft, DUPR ili članova organizacija |
| `["fed", "mfa"]` | Članova organizacija, koja je javila višefaktorsku prijavu |

Ako vaša aplikacija traži drugi faktor, provjerite sadrži li `amr` vrijednost `mfa`. Ako ne
sadrži, recite članu neka u Sportyju uključi dvofaktorsku prijavu.

### Claim `clubs`

Uz opseg `clubs` dobivate klubove kojima član pripada: one u kojima ima članstvo koje nije
isteklo ili ulogu u osoblju. To je dovoljno da odgovorite na pitanje „je li ova osoba član kluba X”
bez [partnerskog API-ja](/hr/oauth/partner-api).

```json
"clubs": [
  {
    "id": 42,
    "name": "TK Jarun",
    "url": "https://tkjarun.hr",
    "membership": { "name": "Godišnja", "end": "2027-03-31T23:59:59+00:00" },
    "roles": []
  },
  {
    "id": 77,
    "name": "Padel Centar",
    "url": null,
    "membership": null,
    "roles": ["cashier"]
  }
]
```

`membership.end` je `null` za članstvo bez datuma završetka. `roles` može sadržavati `admin`,
`cashier` i `employee`.

## Prompt i max_age

Oba idu u [zahtjev za autorizaciju](/hr/oauth/authorization-code).

| Pošaljete | Što se događa |
| --- | --- |
| `prompt=none` | Ništa se ne prikazuje. Ako je član prijavljen u Sporty i već je odobrio sve što tražite, odmah dobivate kod. Inače na URI za preusmjeravanje dobivate `error=login_required`, `consent_required` ili `interaction_required`. Koristite to za tihu provjeru je li netko još prijavljen. |
| `prompt=login` | Član se prije odobravanja ponovno prijavljuje u Sporty, čak i ako je već prijavljen. |
| `max_age=600` | Isto, ali samo ako je njegova Sporty sesija starija od 600 sekundi. Zatim provjerite `auth_time`. |
| `prompt=consent` | Prikazuje se zaslon za odobrenje. Sporty ga ionako uvijek prikazuje osim uz `prompt=none`, pa ovo ništa ne mijenja. |
| `login_hint=ada@example.com` | Unaprijed popunjava adresu e-pošte na stranici za prijavu. |

`prompt=none` ne može se kombinirati s drugim vrijednostima.

## Odjava

Kad se netko odjavi iz vaše aplikacije, pošaljite ga na `end_session_endpoint`:

```
https://api.sporty.plus/oauth2/logout
  ?id_token_hint=THE_ID_TOKEN
  &post_logout_redirect_uri=https://yourapp.example/signed-out
  &state=RANDOM
```

| Parametar | Napomene |
| --- | --- |
| `id_token_hint` | id_token koji ste dobili. Može biti i istekao. |
| `client_id` | Umjesto hinta, ako ga više nemate. |
| `post_logout_redirect_uri` | Neobavezno. Mora biti jedan od URI-ja za preusmjeravanje nakon odjave koje ste registrirali. |
| `state` | Neobavezno. Vraća se uz preusmjeravanje. |

Sporty pita člana želi li se odjaviti i iz Sportyja, a zatim ga šalje na vaš
`post_logout_redirect_uri`. Sporty ne opoziva vaše tokene: ako vaša aplikacija treba zaboraviti
člana, [opozovite](/hr/oauth/authorization-code) ih sami.

## Provjera

Dohvatite `https://api.sporty.plus/oauth2/jwks`, odaberite ključ čiji `kid` odgovara zaglavlju
tokena, provjerite RS256, a zatim provjerite `iss`, `aud` i `exp`.

```bash
curl https://api.sporty.plus/oauth2/jwks
```

Spremite JWKS u predmemoriju — sat vremena je razumno — ali kad naiđete na `kid` koji ne
poznajete, ponovno ga dohvatite umjesto da javite pogrešku.

## /userinfo

id_token je snimka stanja. Za trenutne vrijednosti:

```bash
curl https://api.sporty.plus/oauth2/userinfo \
  -H "Authorization: Bearer $ACCESS_TOKEN"
```

Isti claimovi, uvjetovani opsegom na isti način, uvijek uključujući `sub`.

## Rotacija ključeva

Ključ za potpisivanje mijenjamo rijetko, a kad to učinimo:

- novi javni ključ pojavljuje se u JWKS-u, uz stari, prije nego što se njime išta potpiše;
- **svaki postojeći pristupni token prestaje raditi.** Ključ za potpisivanje dijele i pristupni
  tokeni, pa ih rotacija poništava. Vaši refresh tokeni to preživljavaju — iskoristite ih i budite
  spremni na ponovnu autorizaciju ako to ne uspije.

Ako ikad vidite da je token koji izgleda valjano iznenada odbijen, jednom ga osvježite prije nego
što zaključite da je nešto pokvareno.
